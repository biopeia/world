# World

Incremental Biopeia World extraction. This repository currently contains a bounded, transport-neutral causal journal and a minimal synchronous causal coordinator; it is not yet a complete World runtime.

`WorldRuntime` coordinates one active presence and an opaque transition callback. It invokes the callback for the proposed tick, then appends one committed causal record. Only one tick may be in progress: concurrent or reentrant calls fail fast with `TickInProgressError` before invoking their callback and do not change runtime status. If the callback or append fails, the runtime enters `RECOVERY_REQUIRED` and refuses further ticks. The callback runs before publication; it may already have mutated participant state when it fails, and this prototype performs no rollback or recovery.

The journal/runtime coordinate World-scoped causal records without owning Organism-private state, Embodiment somatic state, or Environment state. Event types are opaque here: this package does not define which authority owns their semantics. IDs and tick numbering are deterministic; there is no RNG or host-clock dependency.

`DurableWorldRuntime` composes the manifest store with a durable immutable journal-prefix store and an owner-checkpoint writer/verifier callback. Before the callback may persist a proposed causal tick, World publishes `RECOVERY_REQUIRED`. It publishes `COMPLETE` only after the callback returns opaque owner references, the dependency verifier accepts them, and the journal prefix is durable. Manifest schema v2 records the active presence ID(s); restore rejects a caller-supplied presence that is not in the persisted causal cut.

This remains a bounded coordinator, not a general crash-recovery protocol. `recover_previous_cut` is an explicit, caller-authorized rollback to the last committed cut: it verifies that cut's owner checkpoint references and journal, delegates restoration opaquely to owner callbacks, re-verifies the references, writes an immutable recovery receipt, then republishes that prior cut as `COMPLETE`. Normal `restore` similarly verifies references before and after delegated owner restoration and returns no runtime if the dependency closure changes during restoration. The owner restorer must be retry-safe because a partial restoration may leave `RECOVERY_REQUIRED` set during explicit recovery. If owner restoration or publication fails, callers must handle the failure explicitly; this check does not create a general persistent recovery marker for normal `restore`. The callback must provide the exact semantically complete owner dependency closure—hash availability alone does not prove that it included every participating authority. The manifest persists the presence IDs for this cut, but there is no presence registration/termination API or multi-presence transition orchestration yet. Process/power-loss crash consistency, multi-process writer coordination, and platform durability behavior remain unverified. Do not infer full AD-0019 compliance from these API-level tests.
